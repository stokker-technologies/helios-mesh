# Harmonize Conventions And Release

## Why

Repository automation predates project-owned CI and the published library still advertises itself as unpublished. Connection failures need actionable diagnostics without speculative hardware changes.

## What Changes

- Migrate metadata, hand-owned guidance, tool pins, build locks, caches and project-owned CI using fresh Dokime and Harmos reference revisions.
- Preserve protocol 14, public error variants, operation deadlines and firmware contracts; fix only demonstrated connection defects.
- Update current usage and publication documentation and publish the next patch through the protected release flow.

## Impact

One integration branch owns configuration, tooling, affected host paths, deterministic tests and documentation. The primary checkout and other worktrees remain untouched. No full local simulation is requested; hosted native Linux and Windows release proof is required.
